# Dispatcher, worker leases and recovery

Status: proposed production orchestration protocol. The [local worker](../local-service.md) implements a single-process subset with fenced completion and terminal recovery, not ECS dispatch or automatic retries. PostgreSQL is the durable authority. No assumption of exactly-once ECS or provider execution is made.

1. Dispatcher polls every 2 seconds. In a short transaction use `FOR UPDATE SKIP LOCKED` on eligible outbox rows. Lock project/global capacity records in a stable order; reserve one attempt and its budget, generate a random fencing token and persist a stable RunTask client token. Transition `QUEUED` to `DISPATCHING` and commit.
2. Outside the transaction call ECS RunTask with the persisted client token and identical parameters: exact task definition revision/image, job/attempt/fence, project role, private network and resource limits. Store the task ARN when known. Retries of an ambiguous RunTask reuse the token; do not create a new attempt merely because the HTTP reply was lost. ECS token idempotency has a bounded lifetime, so it is supplementary to database fencing ([AWS documentation](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ECS_Idempotency.html)).
3. Worker atomically claims the reserved attempt with its fence, changes it to `ACTIVE` and job to `RUNNING`. A duplicate task cannot claim an already-active attempt and exits without calling providers. Heartbeat every 10 seconds, lease 60 seconds using DB time. Startup reservation expires after 180 seconds; the reconciler checks ECS task state before replacement and revokes the fence transactionally.
4. Worker verifies bytes, runs evaluation, uploads evidence, then commits only if attempt/fence/state/deadline/cancellation still permit it. Completion writes report+gate+terminal state+budget settlement in one transaction. Heartbeat loss stops new calls immediately; local timers must fail closed before lease expiry.
5. Reconciler runs every 15 seconds, compares overdue leases with ECS state, revokes stale fences and requests StopTask. Release capacity only after task termination is observed or conservative lease/quota expiry proves no new calls can be admitted. A replacement can run after fencing, but capacity accounting still includes a potentially live old task. Attempts exhausted or deadline reached becomes `FAILED`; otherwise move through `RETRY_WAIT` back to `QUEUED`.

Outbox claims use a separate short dispatch lease; delivery marks are not proof that an evaluation completed. A crash before RunTask retries the same reservation; a crash after RunTask reconciles the known token/task. Expired RunTask token with ambiguous old launch requires ECS inspection and fence revocation before a new attempt. EventBridge ECS stop notifications may accelerate reconciliation later; polling remains the correctness path.

The core SQL scaffold uses one `JOB_READY` outbox row per job. Transitioning `RETRY_WAIT` back to `QUEUED` atomically clears that row's delivery/claim fields, making it eligible again. The dispatcher checks current job state before acting on any replay. A future event-history table may retain every delivery separately; it must not alter this replay-safe behavior.

Retry ownership is explicit. Provider layer: at most 2 retries (3 calls total) for timeout/429/5xx with full jitter, honor Retry-After, per-call timeout 30 seconds. Disable or account for engine/SDK internal retries to prevent multiplication. Attempt layer: at most 3 attempts for launch loss, worker crash and exhausted transient provider failure, delays 10 then 30 seconds plus jitter. All limits are subordinate to absolute job deadline, project rate limits and reserved monetary budget. Provider-auth, malformed engine output, invalid config and integrity errors fail immediately. Quality results do not trigger retries.

Budget and concurrency are durable controls, not just `asyncio.Semaphore`. Reserve worst-case tokens/cost before each call in PostgreSQL under a project/provider-account quota key; release the call slot after completion and settle actual usage. Include candidate generation, all judge calls, embeddings and retried calls. Unknown completion retains its worst-case spend until reconciliation. Use expiring slot leases plus heartbeat and conservative in-flight timeout; a dead worker's call may still bill. Enforce a job-level maximum output token count at the provider and cancel outstanding work on budget exhaustion.

Deadline starts at admission. Reconciler expires queued jobs as well as running jobs. Completed external calls whose response is lost may be repeated and charged; record each call attempt and provider request ID when available. A new job never claims an old job's partial outputs as fresh evidence. A future resumable mode needs separate semantics; v1 restarts an attempt and reports total spend across all attempts.

Recovery drills: kill dispatcher before/after launch; duplicate RunTask; pause worker heartbeats; crash between upload and DB commit; cancel during final commit; simulate DB outage and provider 429. Acceptance: one authoritative terminal report, no stale publication, bounded active calls, no quota leaks after reconciliation, gate never passes on incomplete execution.
