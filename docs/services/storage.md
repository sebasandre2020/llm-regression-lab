# Artifact registry and persistence

Status: production storage specification. [Local verified filesystem storage and migrations](../local-service.md) are implemented; S3 and retention remain planned. [Version API](../api/versions.md) defines canonicalization; [core SQL](../../infra/postgres/001_scaffold.sql) is still incomplete for production.

Object keys: `projects/{project_id}/versions/{kind}/{digest}/document.json`, `projects/{project_id}/jobs/{job_id}/attempts/{attempt}/cases.jsonl`, and `projects/{project_id}/reports/{digest}/report.json`. Immutable registry/report writes use conditional create, checksum validation and stored S3 VersionId. Workers read exact key+version and recompute SHA-256; an ETag is not a SHA-256 checksum. Store report digest externally in DB; the content digest excludes no fields because the digest is not embedded in the hashed payload. API `artifact_digest` is an envelope field added around the stored report document.

S3 versioning alone does not prevent overwrite. Application writes are create-only, IAM restricts ordinary deletion, and reads use pinned VersionId/hash. A future Object Lock retention policy is a separate legal/operational decision. Database uniqueness prevents two different reports for one job; successful finalization is fenced and transactional. Operator roles own retention/deletion, not workers.

PostgreSQL keeps small metadata, references, state, leases, outbox and quota reservations. Use composite project FKs and indexes `(state, next_attempt_at)`, `(lease_expires_at)`, `(project_id, created_at)`. Application connections cannot bypass RLS. Migrations run as a separate one-shot role and use expand/contract upgrades; RLS and grants must be present before any multi-project runtime is exposed.

Retention sweep daily: protect registered versions referenced by live jobs/baselines; delete unreferenced attempt artifacts after seven days, raw observation contents after 30 days, terminal report/job metadata after 365 days unless pinned by active baseline policy. Delete all noncurrent S3 versions too; bucket lifecycle is a backstop, not the sole policy. Expired registry/report content leaves an audit tombstone and API 410 until metadata retirement. Legal deletion supersedes pinning and makes dependent comparisons unavailable explicitly.

Backups: RDS automated PITR with proposed 14-day window; quarterly restore drill to an isolated environment. S3 versioning and optional replication per approved RPO; versioning is not protection from privileged deletion. Restores reconcile DB references against object versions and mark missing evidence unavailable. Do not replay old outbox blindly into production after restoring: disable dispatch, fence all active attempts, inventory ECS tasks and settle quota before reopening.
