# Evaluation and provider adapters

Status: proposed production evaluator contract. The [implemented local worker](../local-service.md) uses only a fake provider and built-in deterministic assertions. Input is a verified dataset/config snapshot plus attempt context; the target output is normalized case observations, execution manifest, aggregates and an execution outcome. Real engines remain planned behind `EvaluationAdapter`.

The worker first calls the approved application target for every `(case_id, repetition)`, recording answer, retrieved contexts, provider usage and timings. Application targets are registry-bound adapters accepting the case input, pinned prompt/model/retrieval revisions and token limits. Frozen dataset contexts support replay suites; retrieval-change suites call the target's retrieval pipeline and record returned context IDs plus corpus/index revision. Do not mix replay and live-retrieval observations in one comparison profile.

| Metric | Engine / definition | Inputs and caveats |
|---|---|---|
| `assertion_pass_rate` | promptfoo normalized boolean assertions, mean per observation | allowlisted equals/contains; all assertions in a case must pass |
| `faithfulness` | Ragas metric pinned by version | answer + retrieved contexts; model judgment is calibrated, not ground truth |
| `context_recall` | Ragas metric pinned by version | input + reference + contexts; reference quality limits interpretation |
| `latency_p95_ms` | service monotonic-clock target-call duration, nearest-rank p95 | include target retries; exclude queueing, judges and engine setup |
| `cost_usd_per_case` | all candidate + judge + embedding + retry estimated cost / expected observations | comparable frozen USD pricing; missing usage is unknown |

Exactly the selected quality metrics must be available for all expected observations; no silently dropping errored rows or averaging only the easiest cases. V1 requires 100% coverage for an actionable gate. Per-metric averaging is macro-average across paired case/repetition observations. Store case-level values so aggregation is recomputable. Generation latency is separate from total job duration; report both in telemetry. Report billed/estimated totals across failed attempts even though quality comes only from the successful final attempt.

promptfoo runs as a non-shell subprocess with a generated, allowlisted configuration, pinned npm lockfile, fixed timeout and JSON output. It evaluates captured outputs so generation is not accidentally duplicated. Its JSON and assertion support are documented upstream ([output formats](https://www.promptfoo.dev/docs/configuration/outputs/), [assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/)). Adapter fixture tests must distinguish assertion failure from process crash/provider error; exit status alone is insufficient. Disable remote providers, custom code assertions, cache and unsolicited telemetry in the release evaluation profile.

Ragas evaluates captured answers/contexts with explicitly supplied judge and embedding adapters. Configure its worker count and retry settings rather than accepting defaults ([RunConfig](https://docs.ragas.io/en/stable/references/run_config/)). Pin the concrete metric/API versions during implementation and store them in the config digest; this phase does not claim compatibility with an installed Ragas release. Run blocking dependencies in a bounded subprocess, never on the API event loop.

One worker's proposed concurrency is 4 external calls maximum; config may lower it, upper bound 8. Run promptfoo and Ragas phases sequentially in v1. Set engine parallelism at or below the same cap and route *every* external call through the shared provider limiter. A local semaphore alone cannot constrain subprocess calls: the planned worker-local provider bridge issues calls on their behalf; direct adapter network access is denied by egress policy. The bridge is internal to the worker, authenticated with an ephemeral credential, has no public listener and rejects unregistered models. Global quota across 16 tasks is enforced in DB (initial proposal 32 concurrent provider calls, plus provider-account RPM/TPM); caps are not multiplied by engine defaults.

Judge calibration: create a versioned, consented reference set with at least 100 human-labeled cases, two independent raters and adjudication; record agreement, confusion by rubric dimension and sensitivity to adversarial instructions. Initial acceptance target is >=0.8 agreement with adjudicated labels and no known critical false passes; this is an unmeasured release criterion, not claimed accuracy. Judge or rubric changes require recalibration and rebuilding paired baselines. Use repeated runs, fixed seeds where supported, frozen reference prompts and confidence intervals. Model aliases are insufficient: use provider revisions where available and record uncertainty when providers cannot guarantee revision stability.
