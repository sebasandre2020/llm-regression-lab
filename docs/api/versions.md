# Immutable dataset and configuration versions

Status: production target with [local registration implemented](../local-service.md). Local storage is filesystem-backed and configs must use the approved fake registry. Registration is inline and synchronous; no upload URL, mutable alias or PATCH endpoint is exposed in v1. [Schemas](../../contracts/schemas.json) define required fields/limits; [dataset fixture](../../examples/dataset.json) and [configuration fixture](../../examples/config.json) are illustrative, not registered resources.

`POST /v1/dataset-versions` accepts `Dataset` with `schema_version: "1.0"`, a name, and 1–1000 uniquely identified cases. Each case contains `case_id`, `input`, `reference`, ordered `contexts` and zero or more assertions (`contains` or `equals`). Text fields are bounded by schema and the entire request by 1 MiB. Contexts are frozen evaluation inputs; an application retrieval adapter may produce candidate contexts for comparison, and must record their corpus/index revision. Case IDs align baseline and candidate observations. Empty inputs, duplicate IDs and metrics missing their required reference/context data are rejected.

`POST /v1/config-versions` accepts `EvaluationConfig`: target registry key, immutable application revision, changed dimensions, prompt digest, model revision, retrieval corpus digest or null, engine image digest, evaluator versions, judge revision, metric policy, pricing snapshot digest, repetitions, seed, concurrency, token and monetary limits. Actual providers, endpoints and credentials are resolved by an administrator-owned registry. A user cannot supply arbitrary code or endpoints. Configs may select approved promptfoo/Ragas adapters, not general engine YAML.

Registry publishing is a planned operator tool, outside the public v1 API: review prompt bytes, target adapter, allowed model/retrieval revisions, engine digest, pricing snapshot and approved gate policy; store each by content digest; then authorize those references for a project. Admission rejects missing/unapproved refs with 422. Resolving a registry key must yield a pinned manifest stored with the job, never a mutable endpoint/prompt policy looked up again mid-run. Registration also validates nonzero budgets, ratios within [0,1], distinct case IDs, and policy approval; these semantic checks supplement JSON Schema.

On registration the server applies validation, materializes all defaults, serializes canonical JSON, stores bytes at a content-addressed key, then inserts the unique `(project_id, kind, digest)` row. Return 201 for first creation, 200 for identical content already present, with `Version` fields: `version_id`, `kind`, `schema_version`, `created_at`. `Location` points to the matching GET. Digest collisions with different bytes fail integrity checks and page the operator; they are not deduplicated.

Canonicalization v1: recursively sort object keys by Unicode code point, preserve array order, emit UTF-8 without BOM, use compact separators, no Unicode normalization, reject duplicate JSON object keys and floats in registered documents. Integers and decimal strings are sufficient for configs. Defaults are included before hashing; do not hash arbitrary client formatting. The serialized canonical bytes are retained and hashed using SHA-256. Future canonicalization changes create a new registry schema version.

`GET /v1/dataset-versions/{version_id}` and `GET /v1/config-versions/{version_id}` return `VersionDocument` containing registration metadata and the validated `document`, with project authorization. Clients needing restricted dataset content require `versions:read`. Unknown/inaccessible versions return 404; retained metadata whose bytes have expired returns 410. No presigned raw data URL is returned by these endpoints.

Langfuse imports are an operator-triggered ingestion process: explicitly select a dataset version, fetch all items, materialize schema and item content, remove prohibited data, canonicalize, and register locally. Never evaluate an unfrozen `latest` dataset. Langfuse versioning is upstream provenance, not this service's immutable ID. Store source version reference separately as audited metadata. See [storage](../services/storage.md).
